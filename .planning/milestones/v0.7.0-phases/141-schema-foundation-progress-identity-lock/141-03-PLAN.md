<objective>
Write the FND-03 data-layer test that locks the progress-identity invariant: adding, removing,
or reordering a materialised technique step must never silently move or orphan an existing
step-completion marker (the v0.2.13 "completed step jumps" class of bug must not recur). Since
the production `resyncTechniqueInstance` is deferred to Phase 144, this test exercises the
schema/SQL invariant DIRECTLY via the better-sqlite3 harness — running exactly the operations
the future resync will perform — and includes a deliberate DELETE+INSERT counter-case proving
the test has teeth.

Purpose: FND-03 is the gate for the entire milestone — it must be locked and proven BEFORE any
technique UI is built. FND-05: the harness uses a single db handle with flat inline SQL (no
nested transactions), the discipline the Phase 144 resync must mirror.

Output: tests/data-layer/technique-progress-identity.test.ts.
</objective>

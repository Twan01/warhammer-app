## Color

Entire color contract is CSS variable-based (shadcn zinc, dark mode). Phase 110 introduces no new colors — all usage is pre-existing.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — dark: zinc 950 | Page and panel backgrounds |
| Secondary (30%) | `hsl(var(--card))` / `hsl(var(--secondary))` — dark: zinc 900 | Cards, table row backgrounds, collapsible content areas |
| Accent (10%) | `var(--faction-accent)` — default zinc-500 (#71717a) | OPG "Used" button active state (variant="default" maps to primary which can use faction accent), collapsible trigger border-left on AbilityEntry |
| Destructive | `hsl(var(--destructive))` — dark: red-600 | Not used in this phase |
| Muted text | `hsl(var(--muted-foreground))` | Weapon stat values, ability descriptions, section labels, empty state copy |
| Border | `hsl(var(--border))` | WeaponTable row dividers, ability card borders, collapsible trigger border |

Accent reserved for: the "Used" Button state on OPG ability toggles (variant="default") only. All other interactive elements use variant="outline" or muted text. Faction accent (`--faction-accent`) is not applied to new elements — maintain existing usage boundaries.

Source: `globals.css`, `UnitAbilityCard.tsx` line 110, `PlaybookDatasheet.tsx` line 148.

### Weapons section in UnitAbilityCard (INT-02)

Position: between OPG abilities section and regular abilities section.

```
CollapsibleContent layout (top to bottom):
  1. [pt-2] Once Per Game section (existing)
  2. [pt-2] Weapons section (NEW — defaultOpen=false)
  3. [pt-2] Abilities section (existing)
  4. [pt-2] Notes section (existing)
```

Collapsible trigger for Weapons section inside `CollapsibleContent`:

```
<div className="flex flex-col gap-2 pt-2">

      </span>

    <CollapsibleContent>
      {/* ranged block + melee block using WeaponTable */}
    </CollapsibleContent>
  </Collapsible>

```

The nested collapsible trigger uses `text-xs` sizing to match the sibling section labels ("Once Per Game", "Abilities") for visual consistency. The ChevronDown is `h-3 w-3` (smaller than the outer card trigger's `h-4 w-4`) to avoid visual hierarchy confusion with the outer card collapse.

Sub-section labels within the Weapons collapsible ("Ranged", "Melee") use `SECTION_LABEL_CLASS` = `"text-xs font-semibold text-muted-foreground uppercase tracking-wide"` matching `PlaybookDatasheet.tsx` line 6–7.

## Interaction Contracts

### OPG Toggle (INT-03 key change)

No visual change. Behavioral change only: key format changes from `unit_id::ability.id` to `unit_id:ability_name`. The toggle renders identically — `Button` variant="default" / "outlined", strikethrough text, opacity-50 on used state.

Zustand persist migration: version bump from 0 → 1. Migration function: for each existing `usedAbilities` key matching pattern `^\d+::\d+$` (old id-based format), drop the key (reset to available). Keys already in `unit_id:ability_name` format are preserved. A one-time reset of in-progress OPG state is acceptable — stated in CONTEXT.md D-07.

### PlaybookTab Canonical Data (INT-01)

No new interaction surfaces. The existing `PlaybookStats` + `PlaybookDatasheet` pipeline is verified and gap-filled. If a unit has a `udb_unit_id` link, weapons and abilities sections will render data. If no link exists, sections render nothing (unchanged behavior — empty state already handled by "No ability data available" message in UnitAbilityCard).

Error state for failed datasheet load: existing pattern — `rounded-md border border-destructive/50 bg-destructive/10 p-3 text-sm text-destructive` with inline error message. No change.

### Validation Warnings (INT-04)

Soft warnings appear in the same location as existing warnings — the army list builder UI. No new UI elements. New warning strings added to the `soft[]` array in `computeListWarnings`:

- `"DEDICATED TRANSPORT count exceeds non-transport, non-character units"`
- `"EPIC HERO must be unique (duplicate detected)"`

The role distribution summary (count per role) is informational — rendered as a single `text-xs text-muted-foreground` line below the existing BATTLELINE soft warning, format: `"Roles: 2 Battleline, 1 Character, 1 Dedicated Transport"`. No chips, no badges — plain comma-separated text matching existing warning line style.

## States to Implement per Requirement

### INT-01: PlaybookTab canonical data verification

| State | Visual |
|-------|--------|
| Unit has `udb_unit_id` link | Weapons + abilities sections render with canonical data |
| Unit has no link, empty stats | DatasheetPicker auto-opens (existing behavior — verify still fires) |
| Datasheet load error | Destructive banner above PlaybookStats (existing pattern) |
| Loading | `opacity-50 pointer-events-none` on container (existing) |

### INT-02: Game Day weapon profiles

| State | Visual |
|-------|--------|
| Unit has weapons data | Weapons collapsible visible, defaultOpen=false |
| Unit has no weapons | Weapons section not rendered (conditional on `datasheet?.weapons?.length > 0`) |
| Weapons section closed | ChevronDown pointing down, WeaponTable hidden |
| Weapons section open | ChevronDown rotated 180deg, WeaponTable visible with ranged/melee splits |
| Loading | Parent card Skeleton covers all sections including weapons |

### INT-03: OPG key stability

| State | Visual |
|-------|--------|
| Fresh install / no existing keys | No migration needed, new keys use `unit_id:ability_name` format |
| Existing old-format keys after upgrade | Zustand version 1 migration clears id-based keys; abilities reset to "Available" state |
| Post-migration | All toggles functional with stable keys |

| DEDICATED TRANSPORT count exceeds limit | Soft warning chip added to army list |

  <action>
    Modify build-unit-db.ts to add three capabilities:

    **1. Multi-pass matching per D-01:**
    Import normalizeName and loadAliases from ./lib/normalize. Load aliases from scripts/data/aliases.json at startup via loadAliases.

    Replace the current single-pass exact-lowercase point matching with a three-pass cascade:
    - Pass 1: Exact lowercase match (current behavior -- bsdataName.toLowerCase() + ":" + factionId lookup in the unitByNameFaction map)
    - Pass 2: Normalized match -- use normalizeName on both BSData name and Wahapedia name, iterate the map entries for matching faction_id
    - Pass 3: Alias fallback -- check aliases[bsdataName], if found use aliased name for exact lookup

    The matching function should be extracted as a local function matchUnit(bsdataName, factionId, aliases, unitMap) returning the matched unit or undefined.

    **2. Sub-faction population per D-09/SF-01/SF-02:**
    Import SUB_FACTION_MAP from ./lib/factionMap. During unit output generation, when a unit comes from a BSData catalogue whose name appears in SUB_FACTION_MAP, set sub_faction to the mapped value. Units from base catalogues (e.g., "Imperium - Space Marines") get sub_faction: null.

    Add sub_faction field to each unit row in the output JSON structure. Ensure it appears alongside existing fields (id, faction_id, name, role, base_points, etc.).

    **3. Coverage report per D-04/DQ-01:**
    After all matching passes complete, compute per-faction coverage stats:
    - For each faction: count total_units, units_with_points (base_points not null OR has entry in points tiers), compute coverage_pct
    - Compute overall aggregate coverage_pct per D-03
    - Collect list of unmatched unit names (units with no points from any source)

    Write the report to scripts/data/coverage-report.json using the CoverageReport interface from RESEARCH.md Pattern 3: built_at, overall_coverage_pct, total_units, units_with_points, factions array, unmatched_units array.

    Also print a console summary during build: per-faction coverage table and overall percentage.

    **4. Add _fr null fields per D-12:**
    Add name_fr: null to each unit, faction, ability, weapon, and keyword row in the output JSON. These are placeholders for Phase 111 population. Include them in the JSON structure so the Rust import (Plan 03) can handle them.
  </action>

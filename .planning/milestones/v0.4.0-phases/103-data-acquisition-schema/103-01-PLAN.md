    Create migration file `src-tauri/migrations/038_udb_schema.sql` with header comment "Migration 038: Unit Database Schema". Per D-09, D-10, implement these 9 regular tables plus 1 FTS5 virtual table:

    1. `udb_factions` — TEXT PRIMARY KEY (id), name TEXT NOT NULL, short_name TEXT, updated_at TEXT NOT NULL DEFAULT datetime('now'). Per D-04, faction IDs reuse Wahapedia text IDs like "SM", "NEC".

    2. `udb_units` — TEXT PRIMARY KEY (id), faction_id TEXT NOT NULL REFERENCES udb_factions(id), name TEXT NOT NULL, role TEXT, base_points INTEGER, damaged_w TEXT, damaged_desc TEXT, updated_at TEXT NOT NULL DEFAULT datetime('now'). Per D-03, unit IDs reuse Wahapedia string IDs.

    3. `udb_unit_models` — INTEGER PRIMARY KEY AUTOINCREMENT, unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, line_order INTEGER NOT NULL DEFAULT 0, name TEXT, M TEXT, T INTEGER, Sv TEXT, inv_sv TEXT, W INTEGER, Ld TEXT, OC INTEGER.

    4. `udb_unit_weapons` — INTEGER PRIMARY KEY AUTOINCREMENT, unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, weapon_group INTEGER NOT NULL DEFAULT 1, line_order INTEGER NOT NULL DEFAULT 1, name TEXT NOT NULL, category TEXT, range TEXT, attacks TEXT, skill TEXT, strength TEXT, ap TEXT, damage TEXT, keywords TEXT.

    5. `udb_unit_abilities` — INTEGER PRIMARY KEY AUTOINCREMENT, unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, line_order INTEGER NOT NULL DEFAULT 0, name TEXT NOT NULL, description TEXT, ability_type TEXT.

    6. `udb_unit_keywords` — composite PRIMARY KEY (unit_id, keyword), unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, keyword TEXT NOT NULL, is_faction INTEGER NOT NULL DEFAULT 0.

    7. `udb_unit_points` — INTEGER PRIMARY KEY AUTOINCREMENT, unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, model_count INTEGER NOT NULL, points INTEGER NOT NULL, UNIQUE(unit_id, model_count).

    8. `udb_unit_composition` — INTEGER PRIMARY KEY AUTOINCREMENT, unit_id TEXT NOT NULL REFERENCES udb_units(id) ON DELETE CASCADE, min_models INTEGER NOT NULL DEFAULT 1, max_models INTEGER NOT NULL DEFAULT 1, notes TEXT.

    9. `udb_meta` — INTEGER PRIMARY KEY CHECK(id=1), version TEXT NOT NULL, built_at TEXT NOT NULL, game_system TEXT NOT NULL DEFAULT '40k-10th', unit_count INTEGER, faction_count INTEGER.

    10. FTS5 virtual table `udb_search` — standalone (no content= option): `CREATE VIRTUAL TABLE IF NOT EXISTS udb_search USING fts5(unit_id UNINDEXED, name, faction_name, keywords);` Per D-08.

    Add FK indexes following the pattern in 033_database_hardening.sql:
    - idx_udb_units_faction_id ON udb_units(faction_id)
    - idx_udb_unit_models_unit_id ON udb_unit_models(unit_id)
    - idx_udb_unit_weapons_unit_id ON udb_unit_weapons(unit_id)
    - idx_udb_unit_abilities_unit_id ON udb_unit_abilities(unit_id)
    - idx_udb_unit_points_unit_id ON udb_unit_points(unit_id)
    - idx_udb_unit_composition_unit_id ON udb_unit_composition(unit_id)

    End with `PRAGMA user_version = 38;`

    CRITICAL: No INSERT/seed statements in the migration. DDL only per D-10. Seeding via migration caused a documented boot-loop incident.

    Deferred tables NOT included (EXT-01/02/03): udb_unit_leader_targets, udb_shared_abilities, udb_detachments, udb_detachment_abilities, udb_stratagems, udb_enhancements.

    In lib.rs `get_migrations()`, add the new entry after version 37 (the last entry before the closing `]`):
    Migration version 38, description "udb_schema", sql include_str!("../migrations/038_udb_schema.sql"), kind MigrationKind::Up.

    In db-helpers.ts, add BOTH missing entries to the HOBBYFORGE_MIGRATIONS array after "036_unit_form_simplification.sql":
    - "037_override_flags.sql" (was missing from db-helpers.ts; already exists in lib.rs)
    - "038_udb_schema.sql" (new)
    Update the comment on HOBBYFORGE_MIGRATION_COUNT line from "// 33" to the correct count (should be 38 after adding both entries).

## Integration Check

### Complete Flows (4/5)

1. **Build pipeline shared library** — bsdata.ts exports → both entry scripts import → coverage report + alias validation + threshold → unit_database.json
2. **Translation flow** — translations_fr.json → loadTranslationsFr() → name_fr overlay in unit_database.json (SM/NEC/DG all covered)
3. **Audit pipeline** — audit-faction.ts reads UDB + CSVs → field-by-field comparison → reports with systematic + per-unit errors
4. **Sub-faction filter** — dual-site fix (SQL + client filter) → all 3 surfaces (browser, picker, collection) show generic + specific units

### Broken Flow (1/5)

**Data fix propagation to update-unit-database.ts**

`scripts/update-unit-database.ts` was NOT updated with Phase 114's weapon parsing fix. It still contains:
- `row["Range"]` (should be `row["range"]`) — produces empty range
- `row["keywords"]` (should be `row["description"]`) — produces empty keywords
- `weaponGroupTracker` counter (should use `row["line"]` directly) — produces wrong weapon_group

The current `unit_database.json` IS correct (built by the fixed `build-unit-db.ts`). But running `update-unit-database.ts --write` would silently re-introduce all 3 weapon data bugs.

**Fix:** Import `mapWeaponRow` from `./lib/weaponMapping.ts` and replace the inline weapon-push block (lines 177–203).

## Surface-by-Surface Visual Contract

### 1. `PointsFreshnessBadge` — after Phase 133

**Before:** colored dot (always `bg-green-500`) + `v{version}` text, dot has tooltip.

**After:** `v{version}` text-only badge. The `<Tooltip>` wraps the text span directly.

```
[ v1.0.0+a3f7bc21 ]    ← text-xs text-muted-foreground, tooltip on hover
```

Tooltip text (unchanged): `"Data version {version} (built {built_at})"`

No dot. No color. No freshness tier. The content hash in `version` is the provenance.

### 2. `DataHealthSummaryCard` — after Phase 133

**Before (sync row, lines 39–43):**
```
● Data bundled with app         ← colored dot + getSyncAgeLabel() text
```

**After (honest provenance row):**
```
Data {udbMeta.version}          ← text-xs text-muted-foreground, no dot
```

Example rendered: `Data 1.0.0+a3f7bc21`

If `udbMeta` is loading, keep the existing `<Skeleton className="h-4 w-28" />` in place.
If `udbMeta` is null/undefined after load, render: `Data version unavailable` (text-xs text-muted-foreground).

**Backup row (lines 60–69) — PRESERVE EXACTLY, no changes:**
```
● Backed up 3 days ago          ← BACKUP_FRESHNESS_DOT_CLASS dot + getBackupAgeLabel()
  △ (outdated)                  ← only when hasVersionMismatch() is true
```

### 3. `ReadyToPlayCard` — after Phase 133

**Before (sync row, lines 58–68):**
```
🛡 {unpaintedCount} unpainted   Clock ● {syncLabel}
{unpaintedCount > 0 || freshness === "stale" || freshness === "aging"} → amber badge
```

**After:**
```
🛡 {unpaintedCount} unpainted
```

The entire Clock + dot + syncLabel row is removed. The amber badge logic collapses to `unpaintedCount > 0` only — when zero unpainted, no badge. The `Clock` Lucide import is removed (was only used for the sync row).

Empty-state card (no lists): unchanged — `<Shield size={20} />` + "No army lists yet" + helper text.

### 4. `GameDayReadinessPanel` + `GameDayPage` — after Phase 133

The `freshness` prop is removed from `GameDayReadinessPanelProps`. `PointsFreshnessBadge` rendered inside the panel is unchanged (it sources its own data via `useUdbMeta` internally after the dot is removed). No visual change to the panel's layout — just the prop and `computeListHealthStats` call signature tighten.

### 5. `ArmyListSummaryBar` — after Phase 133

The `freshness` prop is removed. `PointsFreshnessBadge` is still rendered inside `ArmyListSummaryBar` — now showing the text-only badge (per contract §1 above). No layout change.

### 6. `DiagnosticsCard` comment — after Phase 133

Update the inline comment referencing "syncFreshness" to: `// data version is sourced from udb_meta (udb_meta.version contains the content hash)`. No visual change.

## Copywriting Contract

This phase is copy-removal, not copy-addition. The contract below documents what disappears and what remains.

| Element | Copy |
|---------|------|
| Removed: sync freshness label | ~~"Data bundled with app"~~ (getSyncAgeLabel output) — deleted |
| Removed: sync staleness badge | ~~"Sync stale"~~ — deleted (dead branch, D-07) |
| Removed: Clock row label | ~~syncLabel text in ReadyToPlayCard~~ — deleted |
| Kept: honest version badge | `v{version}` — text-xs, tooltip: `"Data version {version} (built {built_at})"` |
| New: honest provenance row | `Data {udbMeta.version}` — replaces sync dot row in DataHealthSummaryCard |
| Loading fallback | `<Skeleton className="h-4 w-28" />` (existing pattern, unchanged) |

Primary CTA: none. This phase has no new actions. Zero "sync", "refresh data", "refresh", or "stale" copy remains on any surface touching bundled unit data after this phase. (Backup staleness uses "outdated" which is legitimate and stays.)

Destructive actions: none in this phase.

# v0.4.2 Code Review Report

**Reviewed:** 2026-06-01T12:00:00Z
**Depth:** standard
**Files Reviewed:** 54

## Summary

Reviewed all 54 files changed in v0.4.2 (Unit Database 2.0). The codebase is generally well-structured with consistent patterns. However, I found 4 critical issues including SQL injection vectors in dynamic query construction, a type drift between build scripts causing data loss in the update pipeline, a division-by-zero risk in the coverage card, and an FTS5 search index that silently drops French translations from keyword search. There are also 8 warnings around missing error handling, inconsistent locale parameterization, and a stale version constant.

## Critical Issues

### CR-01: SQL Injection via String Interpolation in getUdbFactions and getUdbUnitsByFaction

**File:** `src/db/queries/unitDatabase.ts:139-171`
**Issue:** The `locale` parameter is interpolated directly into SQL strings via template literals (`${nameSql}`, `${orderSql}`). Although `locale` is typed as `"en" | "fr"`, the type constraint is only enforced at the TypeScript level. At runtime, any string passed to these functions will be interpolated directly into SQL. If a caller passes unsanitized user input (e.g., from a URL parameter), this is a SQL injection vector. The project convention mandates `$1, $2` positional syntax for all queries.

**Fix:** Use conditional queries or parameterized approaches:
```ts
export async function getUdbFactions(locale?: "en" | "fr"): Promise<UdbFaction[]> {
  const db = await getDb();
  if (locale === "fr") {
    return db.select<UdbFaction[]>(
      "SELECT id, COALESCE(name_fr, name) AS name, short_name FROM udb_factions ORDER BY COALESCE(name_fr, name) ASC"
    );
  }
  return db.select<UdbFaction[]>(
    "SELECT id, name, short_name FROM udb_factions ORDER BY name ASC"
  );
}
```
Apply the same pattern to `getUdbUnitsByFaction` and `getUdbUnitDetail`.

### CR-02: update-unit-database.ts Builds UdbFactionRow and UdbUnitRow Without Required _fr Fields

**File:** `scripts/update-unit-database.ts:155-189`
**Issue:** The `buildUnitDatabase()` function in update-unit-database.ts constructs `UdbFactionRow` objects missing the `name_fr` field (line 155-161) and `UdbUnitRow` objects missing `sub_faction` and `name_fr` fields (line 180-188). The `UdbFactionRow` type requires `name_fr: string | null` and `UdbUnitRow` requires `sub_faction: string | null` and `name_fr: string | null`. This script was not updated when these fields were added in v0.4.2. Running `update-unit-database.ts --write` produces a JSON file missing these fields entirely, which causes the Rust import to insert NULL for those columns -- silently losing all French translations and sub-faction data on any subsequent data update.

**Fix:** Add the missing fields to both the faction and unit construction in `buildUnitDatabase()`, and add the French overlay and sub-faction logic (mirroring `build-unit-db.ts`):
```ts
// Factions
.map((row) => ({
  id: row["id"].trim(),
  name: row["name"].trim(),
  short_name: row["short_name"]?.trim() ?? row["id"].trim(),
  name_fr: null, // populated by overlay
}));

// Units
units.push({
  id,
  faction_id: factionId ?? "",
  name,
  role: row["role"]?.trim() ?? "",
  base_points: null,
  damaged_w: row["damaged_w"]?.trim() ?? "",
  damaged_desc: row["damaged_description"]?.trim() ?? "",
  sub_faction: null,
  name_fr: null,
});
```
Also import `SUB_FACTION_MAP`, `CROSS_FACTION_MAP`, `normalizeName`, `loadAliases`, and `loadTranslationsFr` and apply the same multi-pass matching, sub-faction population, and French overlay logic from `build-unit-db.ts`.

### CR-03: Division by Zero in PointsCoverageCard

**File:** `src/features/data-health/PointsCoverageCard.tsx:44-46`
**Issue:** The `overall.pct` computation divides by `factions.reduce((s, f) => s + f.total_units, 0)` without checking for zero. If all factions have 0 total_units (possible during a partial import or data corruption), this produces `NaN` which propagates to the badge display.

**Fix:**
```ts
const totalUnits = factions.reduce((s, f) => s + f.total_units, 0);
const withPoints = factions.reduce((s, f) => s + f.units_with_points, 0);
pct: totalUnits > 0 ? Math.round((100 * withPoints) / totalUnits) : 0,
```

### CR-04: FTS5 Search Index Excludes French Keyword Translations

**File:** `src-tauri/src/lib.rs:731-738`
**Issue:** The FTS5 index rebuild query concatenates `COALESCE(u.name_fr, '')`, `COALESCE(f.name_fr, '')`, and `COALESCE(u.sub_faction, '')` into the `keywords` column, but it does NOT include `k.keyword_fr`. This means searching in French locale for a keyword by its French translation will return no results. The `keywords` field in `udb_search` only contains `GROUP_CONCAT(k.keyword, ' ')` (English keywords), so French keyword searches silently fail.

**Fix:** Include keyword_fr in the FTS index:
```sql
INSERT INTO udb_search(unit_id, name, faction_name, keywords)
SELECT u.id, u.name, f.name,
       COALESCE(u.name_fr || ' ', '') || COALESCE(f.name_fr || ' ', '') ||
       COALESCE(u.sub_faction || ' ', '') ||
       COALESCE(GROUP_CONCAT(k.keyword, ' '), '') || ' ' ||
       COALESCE(GROUP_CONCAT(k.keyword_fr, ' '), '')
FROM udb_units u
JOIN udb_factions f ON f.id = u.faction_id
LEFT JOIN udb_unit_keywords k ON k.unit_id = u.id
GROUP BY u.id
```

## Warnings

### WR-01: Build Script Version Hash is Not Content-Sensitive

**File:** `scripts/build-unit-db.ts:690-691`
**Issue:** The version hash is computed from entity counts (`factions.length-units.length-weapons.length-...`), not from actual content. If a unit's name, points, or abilities change but the total counts stay the same, the hash remains identical. This means `import_unit_database_inner` (lib.rs:511-513) will skip the re-import because the version string matches, silently ignoring data corrections.

**Fix:** Hash the full JSON content rather than just counts:
```ts
const hash = createHash("sha256").update(JSON.stringify(output)).digest("hex").slice(0, 8);
```

### WR-02: useWahapediaFactionId Does Not Include Locale in Query Key

**File:** `src/hooks/useDatasheet.ts:112-129`
**Issue:** `useWahapediaFactionId` calls `getUdbFactions()` without passing the locale, but the results are cached under `WAHAPEDIA_FACTION_KEY(localFactionName)` which does not include locale. If the user switches locale and faction names change (French names), the stale English cache entry may return incorrect matches. However, since this function does case-insensitive name matching and faction IDs are locale-independent, the practical impact is limited to edge cases where French faction names differ significantly.

**Fix:** Either pass the current locale to `getUdbFactions(locale)` and include it in the query key, or document that this intentionally uses English names for ID resolution.

### WR-03: PlaybookTab Directly Executes Raw SQL Outside Query Layer

**File:** `src/features/units/PlaybookTab.tsx:149`
**Issue:** `handlePickerSelect` calls `db.execute("UPDATE units SET udb_unit_id = $1 WHERE id = $2", ...)` directly, bypassing the query layer (`src/db/queries/units.ts`). This violates the project's layered architecture (UI -> Hooks -> Queries -> DB client). More critically, it does not invalidate the units query cache, so the collection page may show stale `udb_unit_id` values until the next natural refetch.

**Fix:** Add a `linkUdbUnit(unitId: number, udbUnitId: string)` function to `src/db/queries/units.ts` and call it through a mutation hook that properly invalidates `UNITS_KEY` and `UNITS_ENRICHED_KEY`.

### WR-07: useUnitKeywords Matches Multiple Units With Same Name

**File:** `src/hooks/useUnitKeywords.ts:33-38`
**Issue:** The query matches by `LOWER(u.name) = LOWER($1)` which can return keywords from multiple units if different factions have units with the same name (e.g., "Captain" exists in Space Marines and Custodes). The JOIN produces a union of all keywords from all matching units, potentially returning false positives for `isCharacter` or `isEpicHero`.

**Fix:** Add a faction constraint or use `udb_unit_id` instead of name matching:
```sql
SELECT k.keyword FROM udb_units u
JOIN udb_unit_keywords k ON k.unit_id = u.id
WHERE u.id = $1
  AND LOWER(k.keyword) IN ('character', 'epic hero')
```
Pass the `udb_unit_id` from the army list unit row instead of the display name.

### WR-08: reorderArmyListUnits is Not Transactional

**File:** `src/db/queries/armyLists.ts:465-475`
**Issue:** `reorderArmyListUnits` executes individual UPDATE statements in a loop without wrapping them in a transaction. If the app crashes mid-reorder, the sort_order values will be partially applied, leaving the list in an inconsistent order. Other multi-step operations in this file (deleteArmyList, removeUnitFromList) correctly use BEGIN/COMMIT/ROLLBACK.

**Fix:**
```ts
export async function reorderArmyListUnits(
  updates: { id: number; sort_order: number }[],
): Promise<void> {
  const db = await getDb();
  await db.execute("BEGIN TRANSACTION");
  try {
    for (const { id, sort_order } of updates) {
      await db.execute(
        "UPDATE army_list_units SET sort_order = $1 WHERE id = $2",
        [sort_order, id],
      );
    }
    await db.execute("COMMIT");
  } catch (err) {
    await db.execute("ROLLBACK");
    throw err;
  }
}
```

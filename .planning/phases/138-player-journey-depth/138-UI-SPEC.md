## Color

All values are CSS variable references. `--faction-accent` is a runtime-mutable token set by the active faction context (default: zinc-500 `#71717a`).

| Role | Token | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `hsl(var(--background))` | Full-page compare route background, dashboard page background |
| Secondary (30%) | `hsl(var(--card))` / `hsl(var(--secondary))` | Compare column cards (`bg-card border border-border/60`), GoalProgressCard outer container, owned-badge background |
| Accent (10%) | `var(--faction-accent)` | Diff-highlight background (see below), goal progress bar fill, "Set a hobby goal" link text |
| Semantic: muted | `hsl(var(--muted-foreground))` | Period labels, percentage text, points metadata, section header labels |
| Semantic: destructive | `hsl(var(--destructive))` | Not introduced in this phase — no destructive actions |
| Semantic: battle-gold | `var(--battle-gold)` | Completed goal progress bar fill only (reuses GoalCard pattern) |

**Accent reserved for (explicit list):**
1. Diff-highlight cells in the compare view — `bg-faction-accent/15` on cells where any column differs.
2. Goal progress bar fill for active (non-completed) goals — `bg-faction-accent` (exact GoalCard idiom).
3. "Set a hobby goal" empty-state link — `text-faction-accent`.
4. "Add to compare" checkbox/toggle in `UdbUnitRow` when the unit is already selected — `ring-faction-accent` focus ring (inherits from existing shadcn focus pattern).

**Diff highlight opacity:** `bg-faction-accent/15` (15% opacity). This matches the semi-transparent overlay used in existing components (e.g. the hero gradient uses `${activeFactionHex}12`, the GoalCard active progress uses solid `bg-faction-accent`). 15% is sufficient for a subtle "cell differs" signal without obscuring the text. Do not use `/10` (too faint) or `/20` (too prominent relative to text).

Source: `src/styles/globals.css` (token definitions), `src/features/goals/GoalCard.tsx` (progress bar pattern), `src/features/dashboard/DashboardPage.tsx` (hero gradient precedent).

## Surface Specifications

### Surface 1 — Unit Compare Page (`/unit-database/compare`)

**Route:** Registered as a flat sibling of `/unit-database` under `layoutRoute` (NOT a child that requires an Outlet refactor). Path: `/unit-database/compare`. Component: `UnitComparePage`.

**Layout:** Full-page within the app's standard layout shell. Horizontally scrollable compare grid when 3 columns are present on narrow viewports.

```
┌─ PageHeader: "Compare Units" + "Clear" button (ghost) ─────────────────┐
│                                                                          │
│  ┌── Column 1 ──┐  ┌── Column 2 ──┐  ┌── Column 3 ──┐                 │
│  │ Unit name    │  │ Unit name    │  │ Unit name    │                 │
│  │ Faction      │  │ Faction      │  │ Faction      │                 │
│  ├──────────────┤  ├──────────────┤  ├──────────────┤                 │
│  │ Stat block   │  │ Stat block   │  │ Stat block   │ ← diff cells    │
│  ├──────────────┤  ├──────────────┤  ├──────────────┤                 │
│  │ WeaponTable  │  │ WeaponTable  │  │ WeaponTable  │ ← presence diff │
│  ├──────────────┤  ├──────────────┤  ├──────────────┤                 │
│  │ Abilities    │  │ Abilities    │  │ Abilities    │ ← presence diff │
│  ├──────────────┤  ├──────────────┤  ├──────────────┤                 │
│  │ Keywords     │  │ Keywords     │  │ Keywords     │ ← presence diff │
│  ├──────────────┤  ├──────────────┤  ├──────────────┤                 │
│  │ Points       │  │ Points       │  │ Points       │ ← diff cells    │
│  └──────────────┘  └──────────────┘  └──────────────┘                 │
└──────────────────────────────────────────────────────────────────────────┘
```

**Empty / under-2 state:** When `compareIds.size < 2`, show a centered empty state:
- Heading: "Select units to compare"
- Body: "Choose 2 or 3 units from the Unit Database to compare them side by side."
- CTA button: "Browse Unit Database" → navigate to `/unit-database`

**Column card spec:** Each column rendered as `bg-card border border-border/60 shadow-sm rounded-lg p-4 flex flex-col gap-4`. Column header (unit name + faction) uses `text-base font-semibold` + `text-xs text-muted-foreground` for faction name. Column width is `minmax(280px, 1fr)` in a CSS grid (3 equal columns, horizontal scroll on overflow).

**Diff cell treatment:** A cell (stat value, ability row, keyword chip, points tier row) that differs across any column receives `className="bg-faction-accent/15 rounded px-1"` wrapping the value. Cells that are identical across all columns render with no background. This is binary — no "best" or "worst" coloring.

**Stat block layout:** 6 stats displayed in a 3×2 grid inside each column: M, T, Sv, W, Ld, OC. Each cell: `text-xl font-semibold text-center` for the value + `text-xs text-muted-foreground text-center` for the stat label.

**WeaponTable:** Rendered once per column using the shared `src/features/units/WeaponTable.tsx` (deduped in Phase 136, HON-08). No new weapon table variant. The WeaponTable itself does not receive diff styling — diff highlights apply to the weapon name row wrapper (weapon absent in another column → entire weapon row gets the `bg-faction-accent/15` treatment).

**Abilities and keywords:** Rendered as a flat list inside each column. An ability/keyword absent in at least one other column's set gets `bg-faction-accent/15 rounded px-1` on the text element. Present everywhere → no background.

**Points section:** Each points tier (base points + model-count tiers) displayed as `text-sm tabular-nums`. A tier value that differs across columns gets `bg-faction-accent/15 rounded`.

**Section headers within columns:** "Stats", "Weapons", "Abilities", "Keywords", "Points" rendered as `text-xs font-semibold uppercase tracking-widest text-muted-foreground` with a `border-t border-border/40 pt-3 mt-1` separator above each. This matches the existing dashboard section header pattern.

### Surface 2 — Selection Affordance on `UdbUnitRow` + Sticky Action Bar

**"Add to compare" affordance on `UdbUnitRow`:** A small checkbox-style toggle button added to the right end of each row, before the points readout. Rendered as `Button variant="ghost" size="icon" className="h-6 w-6 shrink-0"` with a `GitCompare` icon (16px, Lucide). When the unit is in `compareIds`: icon rendered with `text-faction-accent` color + `bg-faction-accent/10` background. When `compareIds.size >= 3` and the unit is NOT in the set: the button is `disabled` with `opacity-50 cursor-not-allowed`. Touch/click target meets 24px minimum for desktop (icon button is 24×24px; desktop-only app, 44px mobile touch target rule does not apply).

**Sticky "Compare (N)" action bar (`UnitCompareActionBar`):** Appears at the bottom of `DatabaseBrowserPage` when `compareIds.size >= 1`. Disappears when `compareIds` is cleared.
- Background: `bg-card border-t border-border/60 shadow-lg` (elevated over list content)
- Position: `sticky bottom-0 z-10` within the database browser scroll container
- Content: left-aligned count label `"N unit selected" / "N units selected"` in `text-sm font-medium` + right-aligned action group: `Button variant="outline" size="sm"` for "Clear" + `Button variant="default" size="sm"` for "Compare (N)" (disabled when `compareIds.size < 2`, enabled at 2+)
- Padding: `px-4 py-3`

### Surface 3 — "Owned ×N" Badge as Deep Link

**Existing badge appearance:** `Badge variant="outline" className="text-xs shrink-0"` rendering "Owned x{N}" — this visual is NOT changed.

**New interaction:** The badge is wrapped in a `Link` (TanStack Router) to `/collection`. The `onClick` handler calls `useCollectionFilters(s => s.setUdbUnitIdFilter)(unit.id)` before the navigation completes, so the Collection page opens pre-filtered to that unit's owned copies.

**Affordance signal:** The badge gains `hover:bg-secondary cursor-pointer` to signal navigability, without changing its `variant="outline"` border/text appearance. Do NOT add an underline (it reads as a standard hyperlink — the badge shape itself is the affordance). Do NOT change the badge variant or add an external-link icon (too noisy in a list row).

**In `UdbDatasheetSheet` header:** Same treatment — the owned badge in the sheet header becomes a `Link` with identical click behavior. The sheet will close naturally when the navigation triggers (TanStack Router route change unmounts the sheet's parent).

**In `UdbSearchResults`:** Owned badges are added to search result rows using the same `Badge variant="outline"` treatment + the same `Link` deep-link behavior, receiving ownership data from the page-level `ownershipAllMap` prop passed down from `DatabaseBrowserPage`.

### Surface 4 — Dashboard Goal Progress Widget (`GoalProgressCard`)

**Placement:** Left column of the dashboard grid, after the "Hobby Health" section, as a new `<section>` with label "Hobby Goals". This is appended as a sibling `<section>` inside the existing `flex flex-col gap-6` left-column `<div>` in `DashboardPage.tsx`.

**Section header:** `<p className="text-sm font-semibold uppercase tracking-widest text-muted-foreground">Hobby Goals</p>` — exact pattern as existing section headers ("Command Center", "Hobby Health", "By Faction").

**Goal rows (populated state):** Show all non-expired active goals (both `status === "active"` and `status === "completed"`; hide `status === "missed"` to keep the card optimistic). Each goal row:
```
┌─────────────────────────────────────────┐
│ Goal name (text-sm font-medium truncate) │ X / Y (text-xs tabular-nums muted) │
│ Period label (text-xs muted-foreground)  │
│ [████████░░░░░░░░░░] progress bar h-1.5 │
└─────────────────────────────────────────┘
```
Progress bar: `h-1.5 w-full rounded-full bg-border/40` with inner fill `h-1.5 rounded-full transition-all duration-500`. Fill color: `bg-faction-accent` for active goals, `bg-battle-gold` for completed goals (exact GoalCard idiom). Rows separated by `gap-3` within a `flex flex-col`.

**Empty state (no active goals):** A single card (`bg-card border border-border/60 shadow-sm rounded-lg`) with `p-4` content:
- Body: `"No active goals."` in `text-sm text-muted-foreground`
- Link: `"Set a hobby goal →"` in `text-sm text-faction-accent` — TanStack Router `Link to="/goals"`

**Container:** The `GoalProgressCard` renders its rows directly (no outer `Card` wrapper when goals exist — rows are slotted into the `<section>` container). When empty, it renders the single `Card` shell. Max display: all active/completed goals (no truncation — personal collection is small).

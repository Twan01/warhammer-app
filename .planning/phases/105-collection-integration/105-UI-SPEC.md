### Semantic Status Colors (readiness badges)

These follow the existing `StatusBadge` tier system from `src/components/ui/status-badge.tsx`:

| Readiness State | Color Class | Meaning |
|-----------------|-------------|---------|
| All copies done (Varnished / Completed) | `bg-emerald-400` | "done" tier |
| Any copy in progress (Shaded → Based) | `bg-violet-400` | "painting" tier |
| Any copy in prep (Built / Primed / Basecoated) | `bg-slate-400` | "prep" tier |
| All copies not started | `bg-muted-foreground/50` | "not-started" tier |

Readiness dot renders as `h-2 w-2 rounded-full` — matches existing `TIER_DOT_CLASS` pattern exactly.

### Ownership Badge

Accent reserved for: ownership count badge ("Owned ×N") on `UdbUnitRow`.

- Use `Badge` component with `variant="outline"` and `className="text-xs"` — subtle, not competing with unit name
- Badge text: `Owned ×{count}` (e.g., "Owned ×2")
- Badge position: trailing end of row, left of the points column
- Not owned: no badge rendered (clean default, no visual noise)

Source: CONTEXT.md D-09, D-11 (locked decisions)

## Component Inventory

### Modified: `UdbUnitRow`

Current layout: `[name flex-1] [role badge] [points text-right w-20]`

New layout: `[name flex-1] [role badge] [ownership badge?] [readiness dot?] [points text-right w-20]`

- Ownership badge (`Badge variant="outline" text-xs shrink-0`): only when owned count ≥ 1
- Readiness dot (`h-2 w-2 rounded-full shrink-0`): only when owned count ≥ 1, immediately after ownership badge
- Points column: existing `text-xs text-muted-foreground tabular-nums w-20 text-right shrink-0` — unchanged
- Ownership + readiness data passed as props (from page-level Map keyed by udb_unit_id)
- Gap between elements: `gap-3` (matches existing row gap)

### Modified: `UdbDatasheetSheet`

Add "Add to Collection" button. Placement: `SheetHeader` trailing area, or dedicated `SheetFooter`.

Preferred placement: **sticky footer** at bottom of sheet scroll container — this makes it always accessible regardless of datasheet length.

Button spec:
- Component: `Button` with `variant="default"` (primary)
- Label: "Add to Collection"
- Icon: `Plus` from Lucide React, `h-4 w-4`, leading
- Width: full width (`w-full`) within the footer padding
- Footer padding: `px-4 pb-4 pt-2` with a `Separator` above it

Ownership context in sheet header (when unit is already owned):
- Show inline ownership count near the role badge: `Badge variant="secondary" className="text-xs"` with text "Owned ×{count}"
- Button label changes to "Add Another to Collection" when already owned (avoids user confusion)

### New: `UdbOwnershipMap` (data shape, not a component)

- Type: `Map<string, { count: number; worst_tier: Tier }>` where key is `udb_unit_id`
- Built once per faction view at page level
- Passed as prop to `UdbUnitList` → `UdbUnitRow` and `UdbDatasheetSheet`

### Modified: `DiagnosticsCard`

Add `"unlinked_units"` diagnostic type:
- Severity: `"warning"` — renders with `variant="destructive"` Badge per existing pattern
- Badge label: `"unlinked units"` (auto-derived from type replace `/_/g, " "`)
- Description: `"{X} collection units are not linked to the unit database"`
- Count: integer count of units where `udb_unit_id IS NULL`
- All-clear state: existing green dot "All diagnostics passed" already handles the zero-flag case

### Modified: `UnitSheet`

Add read-only "Database Link" field in the optional section:
- Display: `text-sm text-muted-foreground` label "Database link" + value showing linked unit name or "Custom unit (no database link)"
- Only visible in edit mode when unit already exists — not shown in create-from-database flow (the pre-fill is invisible to the user)
- Pre-fill in create mode: `name`, `faction_id`, `category`, `points`, `model_count` are populated from database entry; user can edit all before saving
- No picker UI — linking happens via "Add from Database" flow or backfill migration

## Interaction Contracts

### "Add from Database" Flow

1. User selects unit in database browser → `UdbDatasheetSheet` opens
2. User clicks "Add to Collection" button in sheet footer
3. `UnitSheet` opens in create mode (sheet-on-sheet, same pattern as existing app)
4. Pre-filled fields: name, faction_id, category (from role), points (lowest tier), model_count (min_models or 1)
5. User reviews / adjusts fields, clicks "Save"
6. On success: toast "Unit added to collection", both sheets close, ownership badge on browser row updates immediately via React Query invalidation
7. On error: toast with error message, sheet stays open

Sheet-on-sheet: `UnitSheet` opens at higher z-index. Closing `UnitSheet` returns focus to `UdbDatasheetSheet`. This is the established pattern in the app (e.g., Recipes → RecipeSheet from other pages).

### Ownership Badge Updates

- Data fetched once per faction page load via `useUdbOwnership(factionId)`
- React Query key: `["udb-ownership", factionId]`
- Invalidated by `UNITS_KEY` mutation (useCreateUnit, useDeleteUnit)
- No optimistic update needed — badge updates on next React Query refetch after mutation

### Readiness Aggregate Logic (client-side)

Given array of `{ status_painting: PaintingStatus }` for all owned copies of a unit:

```
worst_tier = min tier index across all copies
  where tier order: not-started (0) < prep (1) < painting (2) < done (3)
```

If worst_tier is "done" → emerald dot
If worst_tier is "painting" → violet dot
If worst_tier is "prep" → slate dot
If worst_tier is "not-started" → muted dot

Computed once when building the `UdbOwnershipMap` — not re-derived per row render.

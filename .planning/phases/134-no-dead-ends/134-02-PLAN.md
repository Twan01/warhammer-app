<objective>
Remove the permanent "Link unit" dead end on the datasheet surface (HON-04).

Today the "Link unit" / "Re-link" button in `PlaybookStats` is `disabled={!wahapediaFactionId}`,
so a unit whose collection faction has no canonical mapping can NEVER be linked. Make the action
always lead somewhere:
(a) remove the `disabled` gate (and use the "Re-link unit" label when already linked);
(b) add a NEW `CollectionFactionLinkDialog` (mirrors `FactionLinkDialog` but Collection→UDB
direction, UDB ids are STRINGS) that persists `wahapedia_faction_id` via `updateFaction`;
(c) wire the dialog + a browse-all fallback into `PlaybookTab`'s Link-unit flow by intercepting
`onPickerOpen`;
(d) add a browse-all path to `DatasheetPicker` via `useUdbSearch` (FTS5) when `factionId` is
undefined, with the 2-char prompt vs no-results states from the UI-SPEC.

Per the locked guardrails: rely on the automatic FACTIONS_KEY → wahapediaFactionId →
downstream-hooks invalidation cascade (no extra manual invalidation), no new migration, no new
pipeline import.

Purpose: Root-cause fix (CONTEXT.md D-04/D-05/D-06) — mapping the faction lights up datasheets,
detachment abilities, and shared abilities for every unit of that faction.
Output: A Link-unit flow that never dead-ends, with green tests and a green build.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI → local SQLite (write) | `updateFaction` sets `factions.wahapedia_faction_id` for the collection faction |
| UI → local SQLite (read) | `useUdbSearch` FTS5 query over bundled `udb_search`; `useDatasheetsByFaction` faction-scoped read |

Local, offline, single-user Tauri desktop app. No network, no auth, no external/network input.
The only write is a single COALESCE-guarded faction-mapping update.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-134-03 | Tampering | `updateFaction` faction-mapping write | accept | Write goes through the existing `updateFaction` query using `$1..$8` parameterization (COALESCE-guarded); this plan introduces no new SQL and no string concatenation |
| T-134-04 | Tampering | `useUdbSearch` browse-all search input | mitigate | `searchUdbUnits` already sanitizes FTS5 special characters and gates at >=2 chars (existing, unchanged); browse-all reuses it rather than building raw SQL |
| T-134-05 | Denial of service | full-table datasheet scan in browse-all | accept | Browse-all uses the indexed FTS5 `useUdbSearch` (min 2 chars), NOT a `SELECT *` over all datasheets — bounded, indexed reads only |

No network, auth, or injection surface is created by this plan; the faction-mapping write is the
only state change and is data-integrity-bounded by the existing COALESCE partial-update.
</threat_model>

## Interaction Flows

### HON-03 — Shared Abilities Tab Flow

```
User selects faction in RulesHubPage Select
  → selectedFactionId is set
  → useDetachmentAbilities(selectedFactionId ?? null) fetches
  → [loading] 3 × Skeleton h-[80px] (identical to Stratagems tab)
  → [loaded, has data] flat list of SharedAbilityCard components
  → [loaded, no data for faction] honest empty state message (see Copywriting)
  → [loaded, has data, search active, no matches] search-filtered empty state
  → Card click → Collapsible opens → description rendered via sanitizeRulesHtml
  → Favorites/notes annotations → existing RuleAnnotationControls + RuleNoteEditor
```

The loading skeleton MUST use exactly the same pattern as the Stratagems and Detachments
tabs: `[0, 1, 2].map((i) => <Skeleton key={i} className="h-[80px] w-full rounded-lg" />)`
wrapped in `<div className="flex flex-col gap-2">`.

### HON-04 — Link Unit Button Flow

#### Path A: Faction already mapped (`wahapediaFactionId !== null`)

```
User clicks "Link unit" / "Re-link"
  → PlaybookTab.handlePickerOpen(): wahapediaFactionId is not null
  → setPickerOpen(true) [existing path, unchanged]
  → DatasheetPicker opens scoped to faction
```

#### Path B: Faction unmapped — user maps then links (`wahapediaFactionId === null`)

```
User clicks "Link unit"
  → PlaybookTab.handlePickerOpen(): wahapediaFactionId is null
  → setFactionLinkOpen(true)
  → CollectionFactionLinkDialog opens
    → user selects canonical faction from Select
    → clicks "Link & open datasheets"
    → updateFaction.mutateAsync({ id: localFaction.id, wahapedia_faction_id: chosenId })
    → FACTIONS_KEY invalidated → wahapediaFactionId resolves
    → setFactionLinkOpen(false) → setPickerOpen(true)
    → DatasheetPicker opens scoped to now-resolved faction
    → [toast success] "Faction linked. Datasheets now available."
  → [on error] toast.error("Failed to link faction. Please try again.")
```

#### Path C: Faction unmapped — user skips mapping, browses all

```
User clicks "Link unit"
  → CollectionFactionLinkDialog opens
  → user clicks "Cancel — browse all instead"
  → CollectionFactionLinkDialog closes (onOpenChange(false))
  → PlaybookTab: onOpenChange receives false → setPickerOpen(true)
  → DatasheetPicker opens with factionId=undefined → browse-all mode
    → search box focused, empty → prompt state shown
    → user types 2+ chars → useUdbSearch returns results → list populates
    → user selects → onSelect(unit_id) → existing linkUdbUnit flow
```

No path ends in a disabled button or an empty list with no route forward.

## Copywriting Contract

### HON-03 — Shared Abilities Tab

| Element | Copy | Context |
|---------|------|---------|
| Tab trigger label | `Shared Abilities` | Existing — do not change |
| Count label | `{N} ability` / `{N} abilities` | Matches Detachments pattern: singular/plural |
| Empty state — no abilities for faction | `No shared abilities for this faction in the canonical database.` | Shown when `searchText` is empty and hook returns zero results |
| Empty state — search filtered to zero | `No shared abilities match your search.` | Existing copy — keep exactly as-is |
| Loading skeleton | No text — skeleton only | Parity with Stratagems/Detachments tabs |
| Card description fallback | `No description available.` | Existing `SharedAbilityCard` — do not change |

Source for empty-state distinction: RESEARCH.md §"Empty state behavior (D-03)". The
two-state empty message corrects the current bug where the search-filtered message fires
even when the user never searched.

### HON-04 — CollectionFactionLinkDialog

| Element | Copy | Notes |
|---------|------|-------|
| Dialog title | `Match Faction to Database` | Action-oriented; mirrors "Link Collection Faction" in FactionLinkDialog but from opposite direction |
| Dialog description | `"{collectionFactionName}" has no canonical match yet. Select the matching army from the Unit Database so datasheets can be linked.` | Inline `<span className="font-medium text-foreground">` for faction name |
| Select placeholder | `Select canonical army...` | Distinguishes from FactionLinkDialog's "Select a faction..." |
| Cancel button | `Cancel — browse all instead` | Communicates the fallback action is not a dead end; `variant="outline"` |
| Confirm button | `Link & open datasheets` | Parallel to FactionLinkDialog's "Link & Add"; disabled until selection made |
| Confirm button — loading state | Disabled during mutation | Prevent double-submit |

### HON-04 — DatasheetPicker browse-all mode

| Element | Copy | Condition |

| Prompt state (browse-all, <2 chars) | `Type at least 2 characters to search all datasheets.` | When `isBrowseAll && search.trim().length < 2` |
| Empty state (search returned nothing) | `No datasheets found. Try a different search term.` | Existing copy — reused for both modes when search ≥ 2 chars and no match |

## CollectionFactionLinkDialog Visual Spec

Mirrors `FactionLinkDialog` exactly in structure. Key differences in content only.

```
DialogContent sm:max-w-md
  DialogHeader
    DialogTitle: "Match Faction to Database"
    DialogDescription: "{collectionFactionName}" has no canonical match yet...
  Select (full width)
    SelectTrigger w-full
      SelectValue placeholder="Select canonical army..."
    SelectContent
      SelectItem per UdbFaction (id: string, name: string)
  DialogFooter
    Button variant="outline" → Cancel — browse all instead
    Button disabled={!selectedId || isPending} → Link & open datasheets
```

Icon: No icon on the confirm button (FactionLinkDialog uses `Link2` — omit here to
keep the dialog lean at ~50 lines and avoid importing an icon purely for decoration).

Select reset: On dialog close (both Cancel and after confirm), `setSelectedId("")` is called
to reset state — matching `FactionLinkDialog`'s `handleOpenChange` pattern.

## Prop-Shape Adapter (HON-03)

The adapter is part of the UI contract because it determines what `legend` badge text
appears on `SharedAbilityCard`.

```
UdbDetachmentAbilityWithDetachment → RwAbility adapter:
  id:          a.id
  name:        a.name
  description: a.description
  legend:      a.detachment_name   ← displayed as muted Badge in card header
  faction_id:  a.faction_id
```

The `detachment_name` as `legend` gives the user immediate context about which
detachment each ability belongs to, visually consistent with how the Stratagems tab
groups by detachment name.

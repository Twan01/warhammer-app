## Surfaces & States

### Surface 1: "From {technique}" Badge — Recipe Editor (RecipeSectionCard)

**Current state (Phase 145):** `TechniqueSectionBadge` renders `Badge variant="secondary"` with `BookOpen` icon. Display-only in editor.

**Phase 146 change:** The badge stays display-only. A separate affordance (detach trigger) is added adjacent to the badge in the section header — not on the badge itself.

**Detach trigger affordance (editor only):**
- A ghost icon button `h-7 w-7` placed immediately after the `TechniqueSectionBadge` in the section header flex row.
- Icon: `Unlink` (h-4 w-4), color `text-muted-foreground`, hover `text-foreground`.
- `aria-label="Detach technique from this section"`.
- Clicking opens the DetachConfirmDialog (AlertDialog).
- This button is hidden in the SectionedTimeline (read-only context) — it appears only inside `RecipeSectionCard` when `isTechniqueOwned === true`.

### Surface 2: "From {technique}" Badge — SectionedTimeline (read-only)

**Current state (Phase 145):** Badge is already rendered via `TechniqueSectionBadge` with `onNavigate` when `techniqueSectionInfoMap` is populated.

**Phase 146 change:** No structural change. Badge remains interactive (onNavigate) in detail view, display-only in Painting Mode. No detach affordance here.

### Surface 3: DetachConfirmDialog (new AlertDialog)

Triggered by the Unlink button in RecipeSectionCard.

```
Title:   "Detach technique?"
Body:    "This breaks the live link permanently. Future edits to "{techniqueName}"
          won't update this recipe."
          [newline]
          "Your current steps and colours are kept."
Cancel:  "Keep link"
Confirm: "Detach"  [variant="destructive"]
```

- `AlertDialog` (not `Dialog`) — semantically a destructive confirmation.
- Cancel button: `variant="outline"`, label "Keep link".
- Confirm button: `variant="destructive"`, label "Detach".
- Loading state on confirm button: "Detaching…" (disabled while mutation is in flight).
- No spinner; disabled state on confirm button is sufficient.

### Surface 4: TechniqueDeleteDialog — Extended (existing Dialog)

**Current state:** Shows `usageCount` with copy "is used by N recipes. Deleting it will remove all applied instances."

**Phase 146 change (two cases):**

**Case A — no live non-detached instances (count = 0):**
Keep existing copy: `"This will permanently remove "{technique.name}" and all its steps. This cannot be undone."`
Confirm button: `variant="destructive"`, label "Delete" (unchanged).

**Case B — N > 0 non-detached live instances:**
Replace description with:
```
"{technique.name}" is live-linked to {N} recipe{N === 1 ? "" : "s"}.
Detaching will bake the current colours into those recipes before
removing the technique. No recipe content will be lost.
```
Confirm button: `variant="destructive"`, label `"Detach {N} recipe{N === 1 ? "" : "s"} & delete"`.
Loading state: `"Detaching & deleting…"` (disabled while mutation is in flight).

Cancel button (both cases): `variant="outline"`, label "Keep Technique" (unchanged).

Note: The prop `usageCount` passed to this dialog must now mean **non-detached live instance count** (not the legacy total usage count). Prop rename or new prop `liveInstanceCount` should be resolved by executor; the display text uses this count exclusively.

## Interaction Flow

### Detach flow (editor)

1. User sees "From {technique}" badge + Unlink button in section header (RecipeSectionCard, isTechniqueOwned = true).
2. User clicks Unlink button → DetachConfirmDialog opens (AlertDialog).
3. User reads warning + reassurance copy.
4. User clicks "Keep link" → dialog closes, no change.
5. User clicks "Detach" → button disabled, label "Detaching…" → mutation runs → on success: dialog closes, toast "Technique detached — now plain recipe content", recipe/section/step/progress/slot-map query keys invalidated. Section re-renders as plain (no badge, no Unlink button, name input enabled, drag handle visible, delete button visible).
6. On mutation error → dialog closes, error toast shown.

### Delete with auto-detach flow (TechniqueLibraryPage / wherever TechniqueDeleteDialog is invoked)

1. Dialog opens with live instance count > 0 (Case B).
2. User reads updated description (names consequence, assures no content loss).
3. User clicks "Keep Technique" → dialog closes.
4. User clicks "Detach {N} recipes & delete" → button disabled, label "Detaching & deleting…" → mutation auto-detaches all live instances then deletes technique → on success: toast "Technique detached from {N} recipes and deleted.", dialog closes, query keys invalidated.
5. On error → toast error, dialog closes.

## Accessibility

- DetachConfirmDialog: `AlertDialog` (Radix) provides focus trap, Escape to dismiss, focus returns to trigger on close.
- Unlink button: `aria-label="Detach technique from this section"`. Positioned visually adjacent to the badge; tab order follows DOM order in section header flex row.
- TechniqueDeleteDialog confirm button: descriptive label includes count ("Detach 3 recipes & delete") — screen reader reads consequence without needing to read description separately.
- Badge remains `BookOpen` icon with `aria-hidden="true"` (icon is decorative, badge text carries meaning).
- No new keyboard shortcuts. Existing shortcuts in Painting Mode (keyboard nav) are unaffected — the Unlink button does not appear in Painting Mode.

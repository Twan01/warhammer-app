## Layout Contract

The `DataManagementTab` component renders inside `<TabsContent value="data" className="mt-4">`. It is a vertical stack of 4 Cards with `space-y-4` between them. No horizontal split. No sidebar. No grid.

Primary focal point: the Factory Reset card at the bottom, distinguished by the `variant="destructive"` button. All other cards use `variant="outline"` — the red destructive button is the single chromatic anchor that draws the eye and signals danger.

### Section Order (top to bottom)

```
1. Data Health Link          ← informational + navigation action
2. Preference Export         ← file write action
3. Preference Import         ← file read action
4. Factory Reset             ← destructive action — always last
```

Destructive section is always rendered at the bottom, visually separated by the natural spacing.

### Card Layout Pattern

Each Card uses `CardContent` with `className="p-6 flex items-center justify-between"`:

```
[Left: Title (text-sm font-semibold) + Description (text-sm text-muted-foreground)]
                                        [Right: Single action Button]
```

This matches the `DataHealthLinkSection` pattern from RESEARCH.md Pattern 1 and the existing BackupCard layout.

## Interaction States

### Data Health Link section

| State | Behavior |
|-------|----------|
| Default | Card renders with "Open Data Health" button (variant="outline") |
| Button click | `useNavigate()` called with `{ to: "/data-health" }` — no loading state needed |

### Preference Export section

| State | Behavior |
|-------|----------|
| Default | "Export Preferences" button (variant="outline"), enabled |
| Exporting | Button shows `<Loader2 className="mr-2 h-4 w-4 animate-spin" />Exporting...` and is disabled |
| Save dialog cancelled | Return silently — no toast |
| Success | `toast.success("Preferences exported")` |
| Error (write failure) | `toast.error("Export failed — check available disk space")` |

### Preference Import section

| State | Behavior |
|-------|----------|
| Default | "Import Preferences" button (variant="outline"), enabled |
| Importing | Button shows `<Loader2 className="mr-2 h-4 w-4 animate-spin" />Importing...` and is disabled |
| Open dialog cancelled | Return silently — no toast |
| Malformed JSON | `toast.error("Could not read file — is it a valid JSON file?")` |
| Invalid structure | `toast.error("Invalid preferences file — missing version or settings")` |
| Success | `toast.success("Imported {N} setting(s)")` where N is count of written keys |

### Factory Reset section

Multi-step confirmation flow (3 steps):

| Step | UI Element | Behavior |
|------|------------|----------|
| Step 1 | "Factory Reset" Button (variant="destructive") in Card | Opens AlertDialog |
| Step 2 | AlertDialog with explanation copy + confirmation phrase Input | "Reset" button disabled until `phrase === "RESET"` |
| Step 3 | "Reset App" Button (variant="destructive") enabled when phrase matches | `invoke("factory_reset")` → `relaunch()` |

AlertDialog state machine:
- `open`: boolean — controls dialog visibility
- `phrase`: string — typed confirmation phrase; reset to `""` on `onOpenChange(false)`
- `isResetting`: boolean — disables both "Keep My Data" and Reset buttons; shows spinner on Reset button

During reset (`isResetting === true`):
- Both "Keep My Data" and "Reset App" buttons are disabled
- Reset button renders: `<Loader2 className="mr-2 h-4 w-4 animate-spin" />Resetting...`
- No way to dismiss — app will relaunch automatically on success

On error (invoke throws):
- `toast.error("Reset failed — ${error.message}")` 
- `setIsResetting(false)` — dialog remains open so user can try again or cancel

## Accessibility Contract

- AlertDialog uses Radix `AlertDialog` primitives — focus is trapped inside dialog when open, `Escape` key closes it (but NOT during `isResetting === true` — add `onEscapeKeyDown={(e) => isResetting && e.preventDefault()}` to `AlertDialogContent`).
- Confirmation Input has a `<Label>` with `htmlFor` matching the Input's `id`.
- All destructive buttons have explicit `aria-label` if icon-only; these are text buttons, so no additional aria attributes needed.
- Loading buttons set `disabled` which removes them from tab order naturally.
- Factory Reset "Reset App" button is `disabled` when `phrase !== "RESET"` — this is the correct pattern (not `aria-disabled`).

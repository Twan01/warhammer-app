| Token | Value | Usage |

| sm | 8px | Compact element spacing, between label and input |
| md | 16px | Default element spacing, between form fields |
| lg | 24px | Section padding, between section heading and content |
| xl | 32px | Between major sections within Preferences tab |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: Drag handle touch target minimum is 32px wide × 32px tall (DnD interaction area for checklist reorder).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page heading ("Settings") | 20px / `text-xl` | 600 / `font-semibold` | 1.2 |
| Section heading ("Hobby Defaults", sub-headings) | 18px / `text-lg` | 600 / `font-semibold` | 1.2 |
| Field label | 14px / `text-sm` | 600 / `font-semibold` | 1.5 |
| Body / description / helper text | 14px / `text-sm` | 400 / `font-normal` | 1.5 |

Notes:
- Exactly 3 distinct sizes in use: 20px (page heading), 18px (section heading), 14px (labels + body).
- Exactly 2 weights: 400 (body/helper) and 600 (headings + field labels). shadcn `<Label>` default of `font-medium` (500) is overridden to `font-semibold` (600) to stay within the 2-weight contract.
- Helper/description text uses `text-muted-foreground` color token.
- Pipeline bucket label inputs inherit `text-sm` (14px) from the shadcn `Input` component.

Source: Existing `SettingsPage` — `text-xl font-semibold` for page title, `text-lg font-semibold` for section heads, `text-sm text-muted-foreground` for description copy.

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` = zinc-950 dark | Page background, tab content area |
| Secondary (30%) | `hsl(var(--card))` = zinc-900 dark | Section containers, hover states on list items |
| Accent (10%) | `hsl(var(--primary))` = zinc-50 dark | Save confirmation, active drag handle |
| Destructive | `hsl(var(--destructive))` = red-600 dark | Delete buttons on checklist items only |

Accent reserved for:
- The "Saved" visual feedback moment (brief color flash on successful inline save)
- Active drag handle indicator during checklist reorder

Destructive reserved for:
- Trash/delete icon button per checklist item (icon is `text-destructive`, no fill until hover)
- On hover: `hover:text-destructive` with `hover:bg-destructive/10` background

Source: `globals.css` dark mode tokens; existing delete patterns across feature cards.

## Interaction Patterns

### Instant Save (onBlur)
All three sub-sections use instant save on blur — no explicit "Save" button. This matches D-14 (per-field save) and aligns with the app's established pattern for toggles/selects in settings.

Visual feedback on save:
- No toast for routine field saves (too noisy for onBlur)
- On error: `sonner` toast with `variant: "error"` — "Could not save setting. Try again."

### Drag-to-Reorder (HOB-02)
Use `@dnd-kit/sortable` (already in project dependencies). Keyboard accessibility: arrow keys move items, Space confirms position.

Drag constraints: vertical axis only (`restrictToVerticalAxis` modifier).

### Add Checklist Item
- User types in the add input and presses Enter OR clicks Add Item button
- Input clears after successful add
- New item appears at the bottom of the list
- Instant save to `app_settings`

### Delete Checklist Item
- No confirmation dialog — single click deletes
- Immediate UI removal + instant save
- Minimum 1 item enforced: delete button disabled when only 1 item remains (disabled state: `opacity-50 cursor-not-allowed`)

## State Contract

All settings reads via `useAppSettings()` from Phase 121 (`src/hooks/useAppSettings.ts`).
All writes via `useUpdateSetting()` mutation with React Query cache invalidation.

Loading state: While `useAppSettings().isLoading` is true, render `<Skeleton>` placeholders:
- Pipeline labels: 5 × `<Skeleton className="h-9 w-full max-w-xs" />`
- Checklist list: 5 × `<Skeleton className="h-9 w-full" />`
- Mission format: 1 × `<Skeleton className="h-9 w-full max-w-xs" />`

Error state: If `useAppSettings().isError`, show inline error message (not full-page):
```
<p className="text-sm text-destructive">
  Could not load settings. Restart the app to try again.
</p>
```
This matches the existing `SettingsPage` error pattern exactly.

## Accessibility Contract

- All `<Input>` elements have an associated `<Label>` (htmlFor linkage)
- Drag handle has `aria-label="Reorder '{item}'"` and `role="button"` via dnd-kit
- Delete buttons have `aria-label="Remove '{item}' from checklist"` (not just icon)
- Sortable list has `role="list"` with `role="listitem"` children
- Disabled delete button (last item) has `aria-disabled="true"` and a tooltip explaining why
- Focus order: pipeline label inputs top-to-bottom, then checklist rows (handle → text → delete), then add input → add Item button, then mission input

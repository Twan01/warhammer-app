## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — zinc-950 dark | App background, page surfaces |
| Secondary (30%) | `hsl(var(--card))` — zinc-900 dark | Cards, sidebar, nav, dialog surfaces |
| Accent (10%) | `hsl(var(--primary))` — zinc-50 dark | Primary action buttons, active states |
| Destructive | `hsl(var(--destructive))` — red-600 dark | Destructive buttons, error text, error icons |

Accent reserved for:
- Primary CTA buttons in dialogs (Save, Confirm destructive)

- FBK-07: Retry button in PlaybookTab error container: `variant="outline"` on `border-destructive/50 bg-destructive/10` background — existing container colors unchanged
- FBK-09: `toast.success()` uses sonner's default green success color — no custom override
- Error icons (FBK-02): `AlertCircle` at `h-12 w-12 text-destructive` — matches RecipesPage pattern exactly

### FBK-05: RuleNoteEditor "Saved" Indicator

Location: inline next to "Your Notes" label, same row or immediately below it.

Visual contract:
- Element: `<span>` with `text-xs text-muted-foreground`
- Content: "Saved"
- Visibility: controlled by a boolean state flag `showSaved`
- Transition: CSS `opacity` transition — `opacity-0` to `opacity-100` on show, then back after 2000ms via `setTimeout`
- Classes: `transition-opacity duration-300` on the span, toggled via opacity utility classes

Implementation approach (Claude's Discretion — D-05):
```tsx
const [showSaved, setShowSaved] = useState(false);
// After upsertNote.mutate succeeds:
setShowSaved(true);
setTimeout(() => setShowSaved(false), 2000);
```

```tsx
<span className={`text-xs text-muted-foreground transition-opacity duration-300 ${showSaved ? "opacity-100" : "opacity-0"}`}>
  Saved
</span>
```

The span always occupies layout space (opacity not display) to prevent label row jitter.

### FBK-06: PlaybookTab Disabled Save Tooltip

Wrapping contract:
```tsx
<TooltipProvider>
  <Tooltip>
    <TooltipTrigger asChild>
      <span>   {/* wrapper span needed — disabled buttons don't fire events */}
        <Button ... disabled={!isDirty || isLoading || upsert.isPending}>
          Save Playbook
        </Button>
      </span>
    </TooltipTrigger>
    <TooltipContent>
      {isLoading ? "Loading..." : "No changes to save"}
    </TooltipContent>
  </Tooltip>
</TooltipProvider>
```

Tooltip only shows when button is disabled. When `isDirty && !isLoading && !upsert.isPending`, the button is enabled and no tooltip appears.

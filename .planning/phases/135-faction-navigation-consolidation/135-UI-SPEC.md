## Spacing Scale

Standard 8-point scale — project-wide convention, locked from Phase 25 onward.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`) |
| md | 16px | Default element spacing (`gap-4`, `p-4`) |
| lg | 24px | Section padding (`gap-6`, `p-6`) — used by `SettingsPage` and `FactionsPage` outer containers |
| xl | 32px | Layout gaps (`gap-8`) |
| 2xl | 48px | Empty state vertical padding (`py-16` = 64px for centering effect) |
| 3xl | 64px | Page-level spacing |

Exceptions: `FactionsEmptyState` uses `py-16` (64px) for vertical centering — retained verbatim per D-08.

**Critical spacing note — double-padding prevention (Pitfall 6):**

`FactionsPage` root is `<div className="flex flex-col gap-6 p-6">`. `SettingsPage` `<TabsContent>` uses `className="mt-4"`. If `FactionsPage` is rendered inside `<TabsContent>` verbatim, the result is: Settings outer `p-6` + FactionsPage inner `p-6` = 48px of horizontal/vertical padding. This is acceptable per D-08 ("reuse verbatim") but the executor should be aware of the visual density.

**Prescribed resolution (Claude's Discretion — tab header de-duplication):** Do NOT suppress the `FactionsPage` `<PageHeader>` via a conditional prop. Instead, render `FactionsPage` inside `<TabsContent value="factions" className="mt-4">` as-is. The `PageHeader` inside a tab serves as the section title for that tab's content and is consistent with the `DataManagementTab` pattern (which also uses section headings internally). The Settings-level `<PageHeader title="Settings" />` and the tab-level `<PageHeader title="Factions" subtitle="Manage your army factions">` are visually distinct (page vs. section scope) and do not constitute a true double-header.

## Tab Contract — Settings "Factions" Tab

### Tab insertion order
The new tab is inserted as the **second** tab (between Preferences and Data):

```
Preferences | Factions | Data | About
```

Rationale: Faction management is operational configuration (more active than Preferences, less technical than Data). Placing it second creates a logical flow: general preferences → faction setup → data tooling → about.

### TabsTrigger
```tsx
<TabsTrigger value="factions">Factions</TabsTrigger>
```
- No icon in trigger (consistent with existing Preferences/Data/About triggers — text only).
- Label: `Factions` (sentence case, no trailing colon).

### TabsContent
```tsx
<TabsContent value="factions" className="mt-4">
  <FactionsPage />
</TabsContent>
```
- `mt-4` (16px top margin) — matches the spacing used by all other `TabsContent` entries in `settings/page.tsx`.
- `FactionsPage` rendered as-is (D-08 verbatim reuse).
- No additional wrapper `div` or `p-6` container — `FactionsPage` already provides its own `flex flex-col gap-6 p-6`.

### Loading/error state
`FactionsPage` manages its own `isLoading` and `isError` states via `useFactions()`. The Settings page wraps its Preferences tab content in an `isLoading` skeleton guard — the Factions tab does NOT need to be wrapped in the same guard because `FactionsPage` handles its own loading state internally. The Settings `useAppSettings` loading state guards Preferences only.

## Interaction Contract

### Faction tab navigation
- Default tab on Settings page load remains `preferences` (unchanged `defaultValue="preferences"` in `SettingsPage`).
- The `factions` tab is activated by clicking the `Factions` trigger. No deep-linking to the tab is required in this phase.

### Faction CRUD flow (inherited, unchanged)
| Action | Trigger | Result |
|--------|---------|--------|
| Create faction | `Add Faction` button in `FactionsPage` header or `FactionsEmptyState` | Opens `FactionSheet` with empty form |
| Edit faction | `onEditFaction` callback from `FactionCard` | Opens `FactionSheet` pre-populated |
| Delete faction | `onDeleteFaction` callback from `FactionCard` | Opens `FactionDeleteDialog` with confirmation |
| Add unit to faction | `onAddUnit` callback from `FactionCard` | Opens `UnitSheet` with `defaultFactionId` pre-set |
| Edit unit | `onEditUnit` callback from `FactionCard` | Opens `UnitSheet` pre-populated |
| Delete unit | `onDeleteUnit` callback from `FactionCard` | Opens `UnitDeleteDialog` |

All Sheet and Dialog components use Radix-managed open/close state. The `key` anti-pattern note in `FactionsPage` (line 118–119) is preserved verbatim.

### Sidebar removal interaction
- After removing Factions from `MANAGEMENT_NAV`, users who navigate to `/factions` directly (bookmarks, deep links) will hit a 404/not-found route. The TanStack Router will render its default not-found component. This is acceptable — the old page is retired and the router entry is deleted.
- Data Health (`/data-health`) route is **kept**. Users who bookmark `/data-health` continue to land on the full Data Health page. The only change is the sidebar entry is gone.

### HON-05 — no user-facing interaction
Migration 048 runs automatically at app startup before the UI loads. The user sees no migration progress indicator. If migration 048 fails (which should be impossible given the no-op characteristic on clean installs), the app will fail to open in the normal Tauri migration failure mode. No UI handling is needed for the migration itself.

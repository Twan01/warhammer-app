## Layout Contract

### Preferences Tab Structure

The Preferences tab content renders as a vertical stack of setting rows inside the existing `TabsContent value="preferences"` container. No additional card wrapper is added around the full tab — each setting row is self-contained.

```
TabsContent[preferences]
  └── div.space-y-6 (gap: 24px between rows)
        ├── SettingRow: Language
        ├── SettingRow: Currency
        ├── SettingRow: Default Faction
        └── SettingRow: Army Readiness Target
```

### Setting Row Pattern

Each setting row uses a two-column layout: description on the left, control on the right.

```
div.flex.items-start.justify-between.gap-4
  ├── div (left: label + description)
  │     ├── p.text-sm.font-semibold          — setting name
  │     └── p.text-sm.text-muted-foreground — description
  └── div (right: control)
        └── [control — see per-setting spec below]
```

Min width on the right control column: `min-w-[160px]` to prevent layout collapse on narrow windows.

No dominant focal point by design — all four setting rows are visually equal weight.

### Language Control

Segmented button group — two buttons in a bordered container, matching the existing `LocaleToggle` sidebar pattern exactly.

```
div.flex.border.border-border.rounded-md.overflow-hidden
  ├── Button[variant=secondary, size=sm] "EN"   — active state
  └── Button[variant=ghost, size=sm] "FR"       — inactive state
```

- Active locale button: `variant="secondary"`
- Inactive locale button: `variant="ghost"`
- Button height: `h-7`, text: `text-xs`
- Both buttons have `flex-1 rounded-none`
- Clicking inactive button calls `useUpdateSetting("locale", next)` then invalidates the 7 query keys from `LocaleToggle`

### Currency Control

shadcn Select dropdown, width `w-[160px]`.

Options (in order):
1. GBP — British Pound (£)
2. EUR — Euro (€)
3. USD — US Dollar ($)
4. CAD — Canadian Dollar (CA$)
5. AUD — Australian Dollar (A$)
6. JPY — Japanese Yen (¥)

Default when no setting: GBP (matching D-05 from CONTEXT.md).

Select trigger shows: currency code + symbol. Example: "GBP (£)".

### Default Faction Control

shadcn Select dropdown, width `w-[200px]`, populated from `useFactions()`.

Options (in order):
1. "None" — at the top, value="" (clears the setting)
2. [faction name] — one per faction from useFactions(), sorted alphabetically

Default when no setting: "None" displayed.

Selecting "None" calls `useUpdateSetting("default_faction_id", "")` or removes the key.
Selecting a faction calls `useUpdateSetting("default_faction_id", String(faction.id))`.

Loading state: Select trigger shows `<Skeleton className="h-9 w-[200px]" />`.

### Army Readiness Target Control

Preset button group + optional custom input stacked vertically, right-aligned.

```
div.flex.flex-col.items-end.gap-2
  ├── div.flex.gap-1  — preset buttons
  │     ├── Button[size=sm] "500"   h-7 px-2 text-xs tabular-nums
  │     ├── Button[size=sm] "1000"  h-7 px-2 text-xs tabular-nums
  │     ├── Button[size=sm] "1500"  h-7 px-2 text-xs tabular-nums
  │     └── Button[size=sm] "2000"  h-7 px-2 text-xs tabular-nums
  └── Input[type=number, placeholder="Custom…"]  w-[120px] h-7 text-xs text-right
```

- Active preset: `variant="default"`. Inactive preset: `variant="ghost"`.
- When custom input has focus or contains a value not matching a preset, no preset button shows as active.
- Custom input: `min=1`, `max=99999`, no spinner arrows (`[&::-webkit-inner-spin-button]:appearance-none`).
- Changing a preset button or blurring the custom input triggers `useUpdateSetting("army_readiness_target", value)`.

## States

### Loading State (settings query in-flight)
- The entire Preferences tab content area shows `<Skeleton className="h-4 w-48" />` — already in Phase 121 shell.
- Individual controls that depend on faction list: show skeleton placeholder for the select trigger.

### Error State (settings query failed)
- Already handled by Phase 121 shell: `<p className="text-destructive text-sm">Could not load settings. Restart the app to try again.</p>`
- No additional error handling at the individual control level — errors from `useUpdateSetting` are surfaced via sonner toast (existing app-wide pattern).

### Save Feedback
- Auto-save on change — no explicit Save button.
- No success toast for individual preference saves (they are low-stakes, immediately visible).
- Error on save: sonner toast `"Could not save setting. Try again."` using `toast.error()`.

## Interaction Contracts

### Auto-Save Behavior
- Each control fires `useUpdateSetting(key, value)` on user action (button click, select change, input blur).
- No debounce needed for button group selections (immediate discrete values).
- Custom points input: debounce 400ms after last keystroke, or fire on blur, to avoid excessive DB writes.

### Locale Change Side Effects
- On language change: call `useUpdateSetting("locale", next)` then invalidate all 7 query keys listed in `LocaleToggle.tsx`.
- The `LocaleToggle` sidebar component must also read from the same `app_settings` source (Phase 122 integration work — outside the UI contract but noted for executor).

### Default Faction "None" Behavior
- Selecting "None" in the faction dropdown visually shows "None" and immediately clears the persisted setting.
- No confirmation required — reversible by selecting another faction.

### Points Target Custom Input
- Typing in the custom input immediately deselects all preset buttons (none show as active).
- If the typed value matches a preset exactly (500/1000/1500/2000), the matching preset button activates on blur.
- Value must be a positive integer. Non-numeric input is rejected silently (HTML `type=number` behavior).
- Empty input on blur: revert to the last valid value (do not write empty to DB).

  <action>
    Create scripts/update-unit-database.ts (per D-24, D-25, D-26). This is a dev-only Node.js script that:

    1. Reads the existing unit_database.json from src-tauri/resources/ as the "old" baseline.
    2. Re-runs the same data acquisition pipeline as build-unit-db.ts: fetches/reads Wahapedia CSVs from scripts/data/ directory, parses BSData XML, builds the full unit database object. Reuse the inlined parseWahapediaCsv function and all parsing logic from build-unit-db.ts (copy or import).
    3. Compares old vs new and produces a DiffReport with:
       - newUnits: units in new but not old (by id)
       - removedUnits: units in old but not new (by id)
       - pointsChanges: units where any points tier value changed (show unit name, old pts, new pts)
       - abilityChanges: units where abilities were added/removed/modified
       - keywordChanges: units where keywords were added/removed
    4. Prints the diff report to stdout in a human-readable format (Markdown-style tables).
    5. If --write flag is passed, writes the new unit_database.json to src-tauri/resources/unit_database.json.
    6. If no changes detected, prints "No changes detected" and exits 0.

    The script runs via: node --experimental-strip-types scripts/update-unit-database.ts [--write]

    The DiffReport comparison logic: iterate all factions, for each faction iterate units, build Maps keyed by unit id. Compare unit-by-unit for points tiers (compare JSON.stringify of sorted tiers), abilities (compare names), keywords (compare sorted arrays).
  </action>
  <verify>
    <automated>node --experimental-strip-types scripts/update-unit-database.ts 2>&1 | head -5</automated>
  </verify>
  <acceptance_criteria>

    - Running without --write does NOT modify unit_database.json

    - Script produces stdout output containing either "No changes detected" or a diff report with sections for new/removed/changed units
    - Script accepts --write flag to write updated JSON
  </acceptance_criteria>

<objective>
Add a persistent, size-capped `frontend.log` on disk fed by frontend error handlers and the boot-failure path, so a broken launch is diagnosable without devtools (REL-08).

Purpose: stderr/stdout are invisible in a packaged GUI release. The worst failure mode — the app never renders (white screen) — currently leaves no trace. This plan makes both JS errors and the `DbHealthGate` failure branch write to disk beside the existing `preflight.log`.

Output: a new infallible `append_frontend_log` Tauri command (clone of `preflight_log` + tail-trim cap), a testable `logFrontend()` JS wrapper, wiring of `globalErrorHandlers` (D-08) and the `DbHealthGate` failure branch (D-09), plus Rust + Vitest tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend (JS) → Rust command | `logFrontend` passes an error-message string across the IPC boundary into `append_frontend_log` |
| Rust command → local filesystem | `append_frontend_log` writes to a fixed path inside the app data dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-132-01 | Tampering | `append_frontend_log` log path | mitigate | Command takes ONLY `line: String`; path hard-coded to `app_data_dir.join("frontend.log")` — no caller-controlled path component, no traversal (V5). |
| T-132-02 | Denial of Service | `frontend.log` unbounded growth | mitigate | `tail_trim_if_oversized` enforces a ~512KB byte cap (D-10) before every append; single-file, no rotation. |
| T-132-03 | Information Disclosure | log line contents | accept | Lines are error messages/stacks only; callers must not pass DB rows/env vars/secrets. Tail-trim caps retained disk footprint. Low value, local-only file. |
| T-132-04 | Denial of Service | logging aborting startup | mitigate | Command returns `()` and swallows every Result; `logFrontend` is fire-and-forget with `.catch(()=>{})` — a log failure can never throw into an error handler and loop. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test caller job -> ci.yml (callee) | A workflow_call could over-share secrets to the callee |
| release job -> GitHub Releases / signing | Publish job holds the signing key + write permission |
| repo admin -> branch protection | Out-of-repo setting that enforces the merge block |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-131-04 | Information Disclosure | release.yml `test` caller job | mitigate | The caller job is `uses: ./.github/workflows/ci.yml` with NO `secrets: inherit`; ci.yml declares no secrets, so the signing key is never passed to the test path. Acceptance: release.yml does NOT contain `secrets: inherit`. |
| T-131-05 | Elevation of Privilege / Tampering | bypass of the publish gate | mitigate | `needs: test` structurally prevents the `release` (publish) job from starting unless the test job succeeds — no `if:` override, no convention. Acceptance: release.yml contains `needs: test`. |
| T-131-06 | Spoofing / Repudiation | unsigned or unpinned-toolchain release | mitigate | Signing secret `TAURI_SIGNING_PRIVATE_KEY` stays scoped to the release job; toolchain pinned to 1.87.0 so a compiler delta can't silently alter the shipped binary. Acceptance: release.yml retains `TAURI_SIGNING_PRIVATE_KEY` and contains `toolchain: 1.87.0`, not `@stable`. |
| T-131-07 | Tampering | merge of red code to master | mitigate | Branch-protection required-status-check (documented, human-actioned in Task 3) blocks merging a PR whose CI is red. This is the only mitigation expressible solely via a repo setting — hence the blocking human checkpoint. |
| T-131-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed (CI-config phase — RESEARCH "Package Legitimacy Audit: not applicable"). No legitimacy checkpoint required. |
</threat_model>

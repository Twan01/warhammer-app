  <action>
    Install @xmldom/xmldom as devDependency (if approved in Task 0): `pnpm add -D @xmldom/xmldom`.

    Create `scripts/build-unit-db.ts` as a standalone Node.js script run via `node --experimental-strip-types scripts/build-unit-db.ts`. Per D-02, this script is dev-side only and never imported by app runtime code.

    At the top of the file, before any other imports, polyfill DOMParser for the browser parsers:
    - Import DOMParser from @xmldom/xmldom
    - Assign it to globalThis.DOMParser so existing parsers work unchanged

    Import the existing parsers:
    - `parseWahapediaCsv` from `../src/lib/parseWahapediaCsv.ts` for CSV parsing
    - BSData parsing functions from `../src/lib/fetchBsdataPoints.ts` (extractTiers, parseCatXml) and `../src/lib/parseBsdataExtended.ts` (parseBsdataModelCounts, parseBsdataLeaderTargets)
    - `FACTION_MAP` from `../src/lib/bsdataCommon.ts` for catalogue-to-faction-ID mapping

    The script reads pre-downloaded source files from `scripts/data/` (gitignored):
    - Wahapedia CSVs: Datasheets.csv, Datasheets_models.csv, Datasheets_abilities.csv, Datasheets_keywords.csv, Datasheets_wargear.csv, Factions.csv
    - BSData .cat XML files from scripts/data/bsdata/*.cat

    Processing pipeline:
    1. Parse Wahapedia Factions.csv into udb_factions rows (id from faction_id column, name from name column). Per D-04, reuse Wahapedia text IDs verbatim.
    2. Parse Wahapedia Datasheets.csv into udb_units rows (id from datasheet id column, faction_id, name, role, damaged_w, damaged_desc). Per D-03, reuse Wahapedia string IDs verbatim.
    3. Parse Datasheets_models.csv into udb_unit_models rows (unit_id=datasheet_id, line_order, name, M, T, Sv, inv_sv, W, Ld, OC).
    4. Parse Datasheets_wargear.csv into udb_unit_weapons rows (unit_id=datasheet_id, weapon_group, line_order, name, category, range, attacks, skill, strength, ap, damage, keywords).
    5. Parse Datasheets_abilities.csv into udb_unit_abilities rows (unit_id=datasheet_id, line_order, name, description, ability_type).
    6. Parse Datasheets_keywords.csv into udb_unit_keywords rows (unit_id=datasheet_id, keyword, is_faction as 0|1).
    7. For each BSData .cat file, use parseCatXml to get tiers, merge into udb_unit_points rows by matching unit name + faction_id via FACTION_MAP.
    8. For each BSData .cat file, use parseBsdataModelCounts to get min/max model counts, merge into udb_unit_composition rows by matching unit name + faction_id.
    9. For units with a single points value (base_points only, no tiers), set base_points on the udb_units row directly.

    Per D-05, output structure is a single JSON object with fields: version (string, "1.0.0"), built_at (ISO 8601 timestamp), game_system ("40k-10th"), unit_count (number), faction_count (number), and arrays: factions, units, models, weapons, abilities, keywords, points, composition.

    Validation before writing (per CONTEXT.md specifics):
    - Every faction must have at least 1 unit; log and exit(1) if any empty faction
    - Total unit count must be >= 100; exit(1) if fewer (likely parse failure)
    - Every unit with point tiers must have at least 1 tier row
    - Log summary: faction count, unit count, models count, weapons count, abilities count, keywords count, points tiers count, composition count

    Write the JSON to `src-tauri/data/unit_database.json` using writeFileSync with 2-space indentation.

    Create the `src-tauri/data/` directory if it does not exist. Add `scripts/data/` to `.gitignore` if not already present (raw source files should not be committed). The `src-tauri/data/unit_database.json` output IS committed per D-02.

    Add a `build:udb` script entry to package.json: `"build:udb": "node --experimental-strip-types scripts/build-unit-db.ts"`
  </action>
